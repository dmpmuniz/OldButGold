## 2. Bugs Críticos (IMPEDEM RELEASE)

### BUG-A01: Badblocks Resume Não Funcional
**Local:** `obg/core/scanner.py:25`, `obg/core/engine.py:147-158`

O parâmetro `resume_offset` é aceito, logged como "safety margin applied", mas **nunca é passado para o comando badblocks**. O comando real é:
```python
command = ["badblocks", "-w", "-s", "-v", device]
# resume_offset chega aqui e é ignorado
```
Badblocks sempre varre o dispositivo inteiro desde o início. A session recovery inteira é cosmética — checkpoints são salvos mas jamais usados. Acceptance tests C-003, C-004, C-005, L-001 falham.

**Spec violada:** SESSION RECOVERY SPECIFICATION §5-8, MASTER SPECIFICATION §9

---

### BUG-A02: Fallback Silencioso para Ferramentas do Host
**Local:** `obg/utils/runner.py:28-38`

```python
def _resolve_tool(name: str) -> str:
    bundle = _bundle_dir()
    if bundle:
        tp = bundle / "tools" / name
        if tp.exists() and os.access(tp, os.X_OK):
            return str(tp)
        logger.warn("BUNDLE", f"Tool '{name}' not in bundle, falling back to host")
    which = shutil.which(name)  # ← fallback silencioso
```

TOOLCHAIN SPEC §20: *"The application shall never silently substitute host-installed binaries. Execution shall stop with a clear explanation."* O código faz exatamente o oposto — substitui silenciosamente com apenas um log WARN.

**Spec violada:** TOOLCHAIN SPECIFICATION §5, §20

---

### BUG-A03: Nenhuma Verificação de Ferramentas na Inicialização
**Local:** `obg/ui/app.py:154-160`

TOOLCHAIN SPEC §12: *"During startup the application shall verify: bundled executable exists; required utilities exist; required shared libraries exist; required files are executable. Missing runtime components shall prevent execution."*

O `StartupScreen._init()` só chama `list_disks()`. **Zero verificação** de tools, libs, ou executabilidade.

**Spec violada:** TOOLCHAIN SPECIFICATION §12, MASTER SPECIFICATION §6 Stage 1
**Acceptance test que falha:** A-001

---

### BUG-A04: Classificação Ignora Falha do Pipeline
**Local:** `obg/core/classifier.py`, `obg/core/engine.py:283-306`

`classify()` só checa SMART attributes e badblocks count. Se badblocks aborta ou o dispositivo desconecta, `_build_result()` ainda chama `classify()` com dados parciais. Um disco que falhou badblocks pode receber **Gold** ou **Silver** se o SMART estava saudável antes.

CLASSIFICATION SPEC §7 define **Failed** como *"validation cannot be successfully completed"* — essa classificação é efetivamente inatingível pelo pipeline normal.

**Spec violada:** CLASSIFICATION SPECIFICATION §7, MASTER SPECIFICATION §13

---

### BUG-A05: `disconnected` Nunca é `True`
**Local:** `obg/core/engine.py:57`

`disconnected = False` é inicializado e checado em todo guard block (`if is_cancelled() or disconnected:`), mas **nunca é setado para `True`** em lugar nenhum. O path de detecção de desconexão não existe.

**Acceptance test que falha:** L-002 (USB Disconnect)

---

### BUG-A06: SMART Re-Collection Descartado
**Local:** `obg/core/engine.py:134`

```python
smart_mid = read_smart(device)  # resultado jogado fora
```

A variável `smart_mid` é atribuída mas nunca lida. O SMART coletado após o Short Self-Test é descartado. O relatório só compara initial com final.

**Spec violada:** MASTER SPECIFICATION §6 Stage 7: *"The updated information shall be presented to the user before validation configuration."*

---

### BUG-A07: SessionDecisionScreen Mostra "Current Stage" Sempre Badblocks
**Local:** `obg/ui/app.py:294`

```python
yield Static(f"  Current Stage: {self.session.get('current_stage', 'Badblocks Validation')}")
```

O dict de sessão (`session.py:create_session()`) **não armazena `current_stage`** — só `session_id`, `created_at`, `model`, `serial`, `firmware`, `capacity_bytes`, `logical_sector`, `physical_sector`, `state`, `badblocks_offset`. O `.get()` sempre cai no default `'Badblocks Validation'`, tornando o campo sempre enganoso.
